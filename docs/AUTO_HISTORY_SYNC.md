# Lead-mediated identity and history synchronization

During authorized dispatch and natural completion, the actual lead follows the
bundled Skill: register the direct parent, preserve the real spawn reference,
read only that parent's public activity, and pass exact path/UUID activity items
to team_bind_agent_activity. A unique match returns the exact child read request.
The lead checks the returned thread ID, excludes reasoning, and imports a bounded
selection of visible messages. Grandchildren use their actual direct parent.

This avoids manual guessing but requires host tools and reliable parent identity.
Missing tools, zero activity, ambiguity and identity conflicts are explicit
failures, not grounds to use a different conversation. A current source read may
need bounded pagination; do not search unrelated histories.

The MCP process never calls model-internal tools itself. State updates while a
lead is naturally waiting are lead-relayed automation, not an independent monitor.
The panel can request another sync; sending a request is not its completion.
